English rewriter experiment log

27 to 29 October 2026 · Finetuning Labs · Measured results and next steps

Luna 6 results

  • GPT-6 Luna passed 73/81 English cases, or 90.1%. One output had a judge-flagged critical error. No outputs were truncated.
  • Luna's mode passes were Slack 16/16, transcribe 27/32, prompt 15/16 and polish 15/17.
  • Both stock models, both uploaded LoRAs and Luna now use the same 81 frozen English inputs, references and Sol rubric.
  • The new 350M LoRA passed 62/81, or 76.5%, with 13 critical-error outputs. The 230M upload is still the older 1,500-row adapter.

See the matched comparison chart and scope below.

1. Experimental setup

  • The goal was a small desktop or laptop rewriter that cleans rough English without changing facts, intent or uncertainty.
  • Created projects/finetuning-labs with separate rules for /slack, /transcribe, /prompt and /polish.
  • Training used the same Colab L4 notebook. Its size preset now couples the model, revision, output directory and adapter repository. Liquid evaluation used Modal A10-family GPUs; Luna used OpenRouter.
  • Code and the notebook stayed in Git, Parquet data and adapters on Hugging Face, and training-loss logs in W&B.

2. How we chose the models

  • Started with LiquidAI/LFM2.5-230M to test the smallest student first. Added LFM2.5-350M after inspecting its remaining errors.
  • GPT-6 Luna supplied the cloud comparison and synthetic examples. Luna Decisions assessed candidates through Arka.
  • GPT-6.1 Sol judged model outputs. Opus verified the earlier data only; later data review and fixes used Sol.

3. Where we started

  • The Local Formatter guide and TypeWhisper behavior defined the task. The first benchmark had 30 TypeWhisper-authored fixtures and 38 new authored examples.
  • Added long paragraphs, numbered sections, quotations, dictionary terms and unchanged cases. Personal transcription history stayed local and outside shared training data.
  • Corrected two references and expanded validation. The current English split has 81 frozen cases; dev has 89. Validation source families stay outside training.

4. How the training data changed

  • Rejected the first 219-pair pilot. Independent review found repeated templates, artificial noise and padded long examples despite passing automatic checks.
  • Built 1,000 reviewed examples from varied scenarios. The 230M LoRA passed 46/81 English cases. Output format improved, but facts and corrections remained weak.
  • Expanded to 1,500 examples with 500 cases targeting corrections, conditions, code and long-text completeness. The historical English score was 51/81, with 17 critical-error outputs and one truncation.
  • Kept its 1,364 English examples and added 500 new English cases, giving 1,864. The additions include 100 long inputs and 125 unchanged pairs, with balanced correction directions.

5. How we used Arka

  • Arka ran its native generation and decision pipeline, extending the earlier cited-answer workflow. Luna authored fictional scenarios, imperfect drafts and mode-specific targets.
  • Luna Decisions checks six dimensions: input plausibility, output quality, facts, intent, literals and mode. Mechanical checks cover duplicates, protected text, unchanged pairs, split overlap and token limits.
  • Reviews covered the exact input, output and pair. Later additions required one Sol pass for strong native decisions, or two for other complete, non-vetoed candidates. Failed and uncertain reviews stayed excluded.
  • The latest 500 pairs retain 942 Sol verification calls. A final targeted review still found three defects; we excluded those pairs and used separately reviewed replacements.

6. How we validated

  • Kept train, dev and validation separate. Dev loss selected checkpoints. Generation received the source and mode instructions, never the reference answer.
  • All five models used the same prompts, 2,048-token output budget and Sol rubric. Liquid used greedy decoding. Hosted Luna used provider-default sampling with reasoning off.
  • A pass requires meaning, literals, mode, readability and output discipline to pass, plus mechanical checks. Missing or truncated outputs count as failures.
  • Reviews bind to exact row hashes. Judgment reuse requires identical packets and judge settings. Viewer rows have input, output, mode and checks. Training rows have system, user and assistant; review metadata stays separate.

7. Where we are now

  • On the same 81 English cases, stock 230M passes 4, its LoRA 50, stock 350M 18, its LoRA 62 and Luna 73. Luna leads the 350M LoRA by 11 cases, or 13.6 percentage points.
  • Critical-error outputs are 17 for the 230M LoRA, 13 for the 350M LoRA and 1 for Luna. Their long-case passes are 4/13, 7/13 and 10/13. Exact unchanged-input preservation is 7/8, 7/8 and 4/8 respectively.
  • The 230M upload still uses the older 1,500-row data. Its earlier 51/81 score becomes 50/81 under the current shared judgment selection because one historical judgment disagrees about unfinished-sentence punctuation. Its weights and outputs did not change.

8. What comes next

  • Recover and upload the newly trained 230M adapter, then compare both sizes trained on the same 1,864 English examples. The saved notebook's model/revision mismatch is corrected in the existing notebook.
  • Add new English scenarios for canceled actions, correction chains, prohibitions and unfinished thoughts. The 350M model still reverses "no network calls" and sometimes retains canceled instructions.
  • Freeze a fresh English evaluation set with human-reviewed references. The current results come from model judgments on reused development validation, not an unseen final test.
